OWNER / LOCAL USERS

Add a workspace user.

Owner alone can create users and MCP tokens. This version cannot delete a user or reset a password in the UI. Protect the local machine and its auth file.

OWNER / READ-ONLY MCP ACCESS

A token that cannot send.

Create a seven-day read-only token for a compatible local MCP client. The secret is displayed once. Store it securely, not in source code, screenshots or a shared document.

Set FARTHING_MCP_TOKEN in the bridge process environment. It is not exposed through the command panel. A token reads local invoice/case data, so connect only an intended client.
WHAT THIS BUILD ENFORCES
  • Passwords salted and hashed with scrypt; no plaintext password storage.
  • Server-side random sessions, HttpOnly + SameSite Strict cookies, eight-hour maximum and thirty-minute idle expiry; restart signs everyone out.
  • CSRF tokens on signed-in mutations, foreign-origin and unexpected-host checks.
  • Five failed local authentication attempts trigger a fifteen-minute cooldown.
  • Server-enforced reader/operator/owner roles; MCP bearer tokens are read-only and expire.
  • Content Security Policy, escaped imported text, frame blocking, no-sniff and no-referrer headers.
  • Local activity trail, not a tamper-proof audit log. No account, recovery, MFA, TLS or penetration-test certification.
The service binds only to 127.0.0.1. Local HTTP cannot use a Secure cookie. Do not expose this service through a tunnel or public host. PayPal keys are server environment variables or the encrypted vault on the Connect PayPal page, never app passwords. Local account setup does not prove PayPal sandbox access.
